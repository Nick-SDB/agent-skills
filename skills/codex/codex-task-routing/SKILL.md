# Codex Task Routing

**先判断当前执行环境，再按任务性质路由。当前代理已经在 Codex 中时，由当前代理直接执行，不嵌套调用 Codex。**

## 环境判断与执行方式

以当前系统身份、宿主提供的运行时信息和会话上下文判断环境；机器上安装了 `codex` 命令，不代表当前代理运行在 Codex 中。

| 当前环境 | 执行方式 |
|---|---|
| 已在 Codex 中，包括 Codex CLI、App、IDE 会话及由 Codex 启动的执行器 | 当前 Codex 直接使用已有工具完成分析、评估、代码修改、实验、验证和报告 |
| 明确处于非 Codex 环境，且任务需要技术执行 | 按下文外部路由流程调用一次外部 Codex，主代理负责审阅与汇总 |
| 无法确认当前环境 | 不自动启动外部 Codex；先核对已有运行时信息，不把信息缺失当成非 Codex 环境 |

## Codex 内直接执行

- 禁止嵌套运行 `codex exec`，也不得通过脚本、包装器或其他调用通道间接启动另一个 Codex 来执行同一任务。
- 不因分析、GPU 实验、代码改动、任务复杂或需要审阅而另起 Codex；当前代理已经是技术执行者，同时持有完整上下文。
- 长任务保留有依赖顺序的任务清单和进度记录，由当前代理依次完成并验证。
- 技术上有风险的路线仍需先审阅：先明确数值契约、算法、布局或测量方法，再检查证据、验证计划及失败后的处理方式，之后实施。
- 这项审阅在当前上下文中完成，不要求另启执行器，也不自动产生新的用户确认步骤；超出用户授权范围时再请求确认。
- 本地命令、测试或实验失败时，由当前 Codex 记录并诊断，按证据修正后继续；不套用下文针对外部 Codex 调用失败的终止规则。
- 本技能不自动要求创建子代理；是否允许并行工作，以当前会话指令为准。

**Codex 环境按本节执行完毕，不进入下面的外部路由流程。**

## 非 Codex 环境的外部路由

以下规则仅适用于已确认当前代理不在 Codex 中的情况。

### 按任务性质拆分

| 子任务性质 | 执行者 | 形式 |
|---|---|---|
| 分析、评估、代码改动，包括问题定位、实验、benchmark 和验证 | 外部 Codex | `codex exec` |
| 文档、规划、跨轮一致性与整体汇总 | 当前主代理 | 直接完成 |
| 仅复述既有上下文，不产生新分析或代码改动 | 当前主代理，或会话已允许的上下文继承子代理 | 不额外启动 Codex |

复杂或长程任务先拆成有依赖顺序的任务清单，标记 `pending`、`in_progress`、`completed`；必要时记录持久化进度。
按清单逐步执行、审阅、验证和汇总，不让多个执行器无依赖地并行处理同一条任务链。

### 外部调用与失败处理

- 使用 `codex exec` 提交自包含任务，提供必要上下文、已确认结论、约束、输入与预期交付物；外部执行器不能假设能看到主会话。
- 明确告知被调用的 Codex：它已经处于 Codex 环境，直接执行任务，不得再次调用 Codex。
- 外部 Codex 的启动、认证、权限或执行器调用出错时，终止该外部子任务并报告原始错误和已有结果；不静默更换执行器、调用通道或由非 Codex 主代理代跑。
- 执行器正常运行期间的测试失败或实验失败是任务证据，由该 Codex 在授权范围内诊断；不将这类失败误判成调用通道失败。
- 查询 CLI 本身状态或账号信息等宿主操作，由主代理直接使用对应工具，无须先启动 Codex 执行器。

### 技术方案审阅

涉及关键数值契约、寄存器或内存布局、算法路线、测量方法等高风险改动时，先让外部执行器提交简短方案，由主代理审阅后再执行。
方案阶段只做必要检查和方案输出，不提前实施尚未审阅的高风险改动；低风险、有界的改动可直接执行。
主代理检查具体证据和验证结果后再汇总，不将执行器的完成声明直接当作已验证事实。

## 场景核对

| 场景 | 应有行为 |
|---|---|
| Codex 用户要求 GPU profiling、修复代码并输出报告 | 当前 Codex 直接完成实验、验证和报告，不运行嵌套 `codex exec` |
| 非 Codex 主代理需要技术执行与文档汇总 | 调用一层外部 Codex 执行技术任务，主代理审阅与汇总 |
| 外部 Codex 已启动，读取到本技能 | 进入“Codex 内直接执行”，不再递归启动 Codex |
| 当前 Codex 的实验报错 | 当前 Codex 诊断并继续授权工作，不因外部路由的失败规则提前终止 |
